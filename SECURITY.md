# Security Policy

Security reports are welcome and should be handled privately.

## Report a vulnerability

Do **not** open a public issue containing exploit details, credentials, tokens, private keys, customer information or other sensitive material.

Use GitHub private vulnerability reporting when it is available for this repository. If that option is not available, contact X1 through the official website and request a private security channel before sending technical exploit details.

Website: https://x1panelhq.com

## Include

When possible, provide:

- affected repository and version/commit;
- affected component or endpoint;
- impact and realistic attack preconditions;
- minimal reproduction steps;
- sanitized logs or screenshots;
- suggested mitigation if known.

Do not include real production credentials or customer data in the report.

## Scope

A security finding should distinguish between source-level evidence, reproducible test evidence and observed runtime behavior. X1 does not treat source presence alone as proof of exploitability in every deployment.

## Coordinated disclosure

Please allow reasonable time for triage, reproduction and remediation before public disclosure. Public disclosure should not expose live credentials, customer data or operational secrets.
